# Website Review

## 1. Interest of content

The site has a clear educational purpose and a strong central idea: each page looks at a different area of computing and explains how it affects society. This makes the project easy to understand at a glance and gives it an obvious academic theme. The topics themselves are relevant and varied, which creates a good starting point for a digital portfolio or coursework project.

However, the content is not always as engaging or convincing as it could be. Some pages feel generic, unfinished or copied rather than carefully developed. For example, the home page in [index.html](./index.html) contains placeholder text such as “Card title” and “Go somewhere”, which makes it feel incomplete. Similarly, [healthcare.html](./healthcare.html) includes a stray item reading “test 5”, which undermines the quality of the page. The pathfinding page also appears to be copied from the speech translation page, with similar title and layout patterns in [Pathfinding.html](./Pathfinding.html), which reduces originality.

The most effective content is in [RemoteComputing.html](./RemoteComputing.html), which is clearer, more detailed and better supported with evidence. [AISpeechTranslation.html](./AISpeechTranslation.html) is also more polished than some of the other pages. Overall, the project has a promising concept, but the content would be much stronger if each page were developed with more care and originality.

## 2. Consistency and quality of visual presentation

The visual presentation of the project is inconsistent and, at times, unfinished. The site does not use one clear design system, so the pages feel disconnected rather than part of a single website. This makes the overall presentation look less professional than it should.

Examples include:

- [index.html](./index.html) uses a basic card layout with placeholder images and generic text.
- [healthcare.html](./healthcare.html) uses different naming and styling compared with the rest of the site, with “Health care” rather than “Healthcare”.
- [Pathfinding.html](./Pathfinding.html) and [AISpeechTranslation.html](./AISpeechTranslation.html) share too many repeated design patterns, suggesting copy-and-paste work rather than a consistent page design.
- The navigation across the pages is not fully consistent, and some links are incomplete or missing.

The website would benefit from a more unified visual identity, including consistent fonts, spacing, headings, colours and page layouts. At the moment, the presentation feels like a set of separate pages rather than a single polished website.

## 3. Quality of written presentation

The writing quality varies considerably across the project. Some pages are readable and well-structured, while others contain spelling mistakes, awkward phrasing and unfinished sentences. This inconsistency makes the site feel less polished and less trustworthy.

Examples from [healthcare.html](./healthcare.html):

- “Health care” and “Healthcare” are used inconsistently.
- “bring healthcare into people home” should be “bring healthcare into people’s homes”.
- “accuracte diagnosis” should be “accurate diagnosis”.
- “Remote computing has help improve patient outcome” should be “Remote computing has helped improve patient outcomes”.
- “it allows rural patient” should be “it allows rural patients”.
- “Eletronic” should be “Electronic”.

These errors may seem small individually, but together they reduce the quality of the written presentation and make the whole page feel less carefully edited. The better-written pages, especially [RemoteComputing.html](./RemoteComputing.html), show that the project has potential, but the standard is not consistent across the full site.

## 4. Validity of HTML

There are several HTML issues that affect the functionality and reliability of the site.

The key issues are visible in the files themselves:

- [index.html](./index.html) contains empty navigation links such as `href=""`, which do not direct users anywhere.
- The homepage still uses placeholder image URLs like `src="..."`, so the images do not display properly.
- The site has inconsistent file naming and casing. For example, [index.html](./index.html) links to `aiSpeechTranslation.html`, but the file is actually [AISpeechTranslation.html](./AISpeechTranslation.html). This can break links on case-sensitive systems.
- [healthcare.html](./healthcare.html) links to `Healthcare.html`, but the actual file is lowercase: `healthcare.html`.
- [Pathfinding.html](./Pathfinding.html) has the incorrect title “Using AI for Speech Translation”, which suggests a copy-and-paste error.
- Several pages use classes that are not standard Bootstrap classes, such as `sm:navbar-expand` and `bg-1 fg-2`, which reduces the expected functioning of the navigation.

Overall, the HTML structure is not fully valid or consistent, and this affects both usability and professionalism.

## 5. Evidence of collaboration including author info not written by author and balanced contributions from members

There is some evidence that the project was created by multiple people, which is positive, but the collaboration is not presented clearly enough. The author information is scattered across the pages rather than organised in a consistent and professional way.

The pages currently show the following authors:

- Ben Kangayan on [RemoteComputing.html](./RemoteComputing.html)
- Charlie Rennison on [Pathfinding.html](./Pathfinding.html)
- Daniel Neale on [AISpeechTranslation.html](./AISpeechTranslation.html)
- Shang kai Huang on [healthcare.html](./healthcare.html)

This does indicate that different members contributed to the site, which is useful evidence of teamwork. However, the author information is not presented in a balanced or clearly structured way. Some links are missing or empty, and there is no shared project credit section or summary that explains who contributed what. In addition, [README.md](./README.md) is currently empty, so there is no clear project overview or contributor record.

This means the collaboration is visible, but it is not yet strong or well-documented. For a collaborative project, author info should be clear, complete and consistent. The current setup shows partial contribution, but not a fully balanced or transparent record of work.

## Conclusion

The project has a good foundation and a clear educational topic, but the site currently feels unfinished in several important areas. The content, visual design, written quality, HTML structure and collaboration evidence all need more attention. With more careful editing, better consistency and a clearer contribution record, the website could become a much stronger and more professional final project.
